# Рубрики судейства: роль backend

Материалы, по которым судьи оценивают ответы собеседования бэкендера.

## Что здесь

| Файл | Что это | Кто использует |
|---|---|---|
| `checklists.json` | якоря чек-листов на все 35 вопросов и 5 уточнений: по 2–4 признака сильного ответа и 1–2 признака слабого | судья яруса 2 (`judge_glm.py`) получает их в промпте; изначально готовились для эксперимента с якорным судейством clef (`judge_checklist.py`) |
| `Q01.md` | полная карточка эталона «Возможности PHP 8+ для чистого кода»: чек-лист сильного ответа, красные флаги, образец сильного ответа, подробная шкала 0–4 | калибровка судейства и ревью владельцем |
| `Q13.md` | полная карточка эталона «Агрегат в DDD», та же структура | то же |

## Формат `checklists.json`

```json
"Q01": {
  "good": [["names_features", "Называет конкретные возможности PHP 8+ (enum, readonly, match...)"],
           ["shows_code", "Показывает короткие примеры кода"]],
  "bad":  [["bare_list", "Просто перечисляет фичи без примеров и объяснения смысла"]]
}
```

- ключи: id вопроса (`Q01`) и уточнений (`Q04.fu1`), всего 41, плюс служебный `_meta`;
- каждый пункт: пара `[код, текст признака]`;
- `good` — признаки сильного ответа, `bad` — слабого;
- факт-корректность конкретики (API, версии, цифры) пунктами не проверяется, это зона судьи яруса 2 с запусками кода.

## Как это работает в судействе

- ярус 1 (decision-модель clef, `judge.py`) оценивает по критериям шкалы,
  зашитым в сам скрипт; эти файлы он не читает;
- ярус 2 (GLM-5.3-Flash, `judge_glm.py`) получает вопрос, ответ кандидата и
  якоря чек-листа этого вопроса («Сильный ответ: …; Слабый: …»), спорные
  факты проверяет запуском кода (PHP, PostgreSQL в docker).

## Почему полных карточек только две

Полная карточка — ручная работа. Две карточки написаны как калибровка
судейства и образец для ревью владельца; якоря `checklists.json` покрывают
все вопросы, и для штатного судейства их достаточно. При изменении вопросника
(версионирование описано в [README корня](../../README.md)) чек-листы
дополняются под новые id.
