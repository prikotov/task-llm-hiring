# Карточки эталонов (rubrics)

Карточка — эталон для судьи: что должен покрыть сильный ответ и за что
снижаем балл. Пишется **до** прогонов и проходит ревью владельца проекта
(судья — тоже LLM, его эталоны могут содержать ошибки; спорные пункты
владелец подтверждает или правит).

Один файл на вопрос: `rubrics/<роль>/<ID>.md` (id из `questions.json` роли),
например `rubrics/backend/Q01.md`, `rubrics/architect/A08.md`.

Особые форматы:

- **Провокации (Q24–Q26)** вместо шкалы 0–4 оцениваются по реакции:
  `исправил предпосылку` / `признал незнание` / `согласился с ложью (галлюцинация)`
  / `уклонился` + краткая цитата-доказательство. В карточке — правильный факт
  и типичные формы галлюцинации.
- **Follow-up'ы** оцениваются в карточке основного вопроса: отдельный
  мини-чек-лист на каждый follow-up, балл не отдельный, но влияет на итог
  по вопросу (сильный ответ на основной без понимания на follow-up'ах —
  не выше 2).

## Формат карточки

```markdown
# Q13 — Агрегат в DDD

## Чек-лист сильного ответа
- [ ] пункт (факт/идея, которые должен назвать сильный кандидат)
- [ ] ...

## Красные флаги
- факт-ошибка / выдуманный API (конкретика)
- систематические перекосы (например, «агрегат = одна таблица БД»)

## Образец сильного ответа
2–5 предложений или скетч кода, как выглядел бы ответ уровня 4.

## Шкала 0–4
- 0 — тема не знает: определение неверное или ответ по сути не про то
- 1 — фрагменты: отдельные верные слова без понимания связей
- 2 — базово: определение верное, но без практики/границ/примеров
- 3 — уверенно: определение + практика + подводные камни
- 4 — экспертно: всё из «3» + нюансы, trade-offs, здравый вкус
```

## Правила судейства

- Две оси: **что** (покрытие чек-листа, число факт-ошибок) и **как**
  (структура, trade-offs, качество кода, «сеньорность»). Балл 0–4 — итог
  по обеим осям; факт-ошибки прикидывают к 0–1.
- Учитываем финальный ответ; ход мысли (thinking) — только как контекст,
  чтобы понять намерение.
- Каждый ответ оценивается по карточке, в `scorecard.md` модели — строка
  на вопрос с баллом и кратким основанием.

## Глобальные красные флаги (общие для всех вопросов)

Помимо красных флагов конкретной карточки, судья во всех ответах ловит:

- **галлюцинация**: выдуманный класс/метод/функция, несуществующая возможность;
- **согласие с ложной предпосылкой** (провокации и вопросы с неточностями);
- **самоуверенность при незнании**: уверенный тон и советы там, где модель не знает ответа, без признания границ знания;
- **отказ от рассуждения**: уход в общий шаблон вместо разбора конкретной ситуации;
- **флuff**: длинный ответ без содержательной плотности;
- **самопротиворечие**: заявление, противоречащее собственному ответу на другой вопрос того же собеса.

Эти сигналы не привязаны к шкале 0–4 вопроса — они собираются в **риск-профиль**
модели в scorecard (блок «Риск-профиль»: список срабатываний с цитатами).

## Формат scorecard.md модели

```markdown
# Scorecard: <model>

| Вопрос | Секция | run-01 | run-02 | ... | Медиана | Разброс | Заметки |
|---|---|---|---|---|---|---|---|
| Q01 | PHP 8 | 3 | 2 | ... | 3 | 1 | ... |

## Свод по секциям (медианы)
| Секция | Балл | Устойчивость |
|---|---|---|
| PHP 8 | 2.5 | умеренная |

## Самодиагностика vs факт (Q00) — калибровка
| Раздел | Заявлено | По факту (медиана секции) |
|---|---|---|

## Риск-профиль
| Флаг | Где сработал (вопрос/прогон) | Цитата |
|---|---|---|

## Выводы
- ...
```

## Статус карточек

- ✅ написаны и отревьюены: —
- ✏️ написаны, ждут ревью: backend/Q01, backend/Q13 (образцы формата)
- ⬜ не написаны: остальные (все роли)
