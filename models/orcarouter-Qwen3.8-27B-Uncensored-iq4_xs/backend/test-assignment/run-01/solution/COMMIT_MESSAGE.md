feat: учёт расходов на LLM-токены — импорт цен/событий, тарификация, CSV-отчёт

Реализовано тестовое задание: PHP 8.4 + Symfony + Doctrine ORM + PostgreSQL 17.

- Схему БД (providers, models, price_rows, usage_events) разворачивает
  миграция `Version20261020200000`: идемпотентный upsert цен, уникальный
  ключ событий (provider_code, provider_request_id), стоимость —
  NUMERIC(20,6).
- `app:prices:import <file>` — JSON-каталог цен: провайдеры (с оф-пиковым
  окном), модели, строки цен; upsert в одной транзакции.
- `app:usage:import <file>` — JSONL-события: полная валидация файла,
  дедупликация по (provider, provider_request_id), запись в одной
  транзакции; дубли игнорируются целиком.
- `app:billing:rate` — тарификация pending-событий строкой с наибольшим
  valid_from <= ts (правосторонняя непрерывность, valid_from включительно),
  оф-пик [start, end) в UTC (окно через полночь поддерживается), бcmath
  (масштаб 20) и единственное округление — HALF_UP до 6 знаков на событии;
  stdout `RATED=<n> UNRATED=<m>`, unrated — по строке в stderr.
  Повторные попытки unrated на каждом запуске.
- `app:billing:report [--from] [--to]` — CSV строго по спецификации:
  группировка (user, "provider/code"), суммы уже округлённых стоимостей
  событий (bcmath, без повторного округления), TOTAL, from включительно /
  to исключительно, unrated не попадают.
- Бонус: `app:billing:reprice <file>` — ретро-правка строк цен и
  пересчёт событий, рассчитанных именно этой строкой; повторный запуск
  той же правки даёт 0 событий (изменяются только реально сменившиеся
  стоимости).

Тесты: 35 unit-тестов PHPUnit (rounding HALF_UP, границы оф-пик, пример из
TASK.md до байта, валидация входов). `make lint` — php -l + Psalm.
Самопроверка: отчёт по fixtures за сентябрь совпадает с ожидаемым из
TASK.md побайтно; повторные прогоны всех команд идемпотентны.
