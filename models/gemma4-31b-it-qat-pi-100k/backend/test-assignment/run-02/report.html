Связанность классов: Ce, Ca, нестабильность I

Ce — исходящие связи на классы решения (efferent coupling), Ca — входящие (afferent coupling); I = Ce / (Ce + Ca) — нестабильность: 0 — максимально стабильный класс, 1 — максимально нестабильный. Здоровая слоистость выглядит так: I близка к 1 у console-команд (точки входа, обязаны меняться часто) и к 0 у примитивов домена (Decimal, Timestamp, enum-статусы): нестабильное должно зависеть от стабильного, не наоборот. Обоснование

ревьюер яруса 3
Обязательная часть формально есть (импорты, сущности, команды), но чекер валит отчёт: report_base и report_duplicates дают неверные суммы (u-alice/prism/lumen-8 3600000 in / 38.885000 вместо ожидаемых) и кривый формат '0.90000' (5 знаков). Ключевой дефект — округление: в bcRoundHalfUp bcadd($value,'0.0000005',6) обрезает аддер до масштаба 6, т.е. вместо HALF_UP происходит усечение (14.26249875 → 14.262498); проверка bccomp===0 и отрицательная ветка мертвы. Цены выбираются корректно (valid_from <= ts, DESC), bcmath используется, но точность денег фактически нарушена. Слой домена не выделен (тарификация в сервисе с EntityManager), N+1 по ценам на каждое событие. Бонус не реализован. По оси B: артефакты COMMIT_MESSAGE.md/PR_DESCRIPTION.md отсутствуют (fail чекера), в дифф заезжен отладочный мусор debug_round.php, мёртвый код в команде rate ($stderr = $output; комментарий «Actually...»), тестов нет, самопроверка по приёмке не выполнена — отчёт байт-в-байт не совпадает.
