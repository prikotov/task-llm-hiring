# Учёт расходов на LLM-токены

## Что сделано

Реализовано консольное приложение на Symfony/Doctrine для импорта истории
цен и событий использования, тарификации и отчёта о расходах. Дополнительно
реализована бонусная команда ретро-коррекции цен.

### Домен и слои

- `src/Domain/*` — сущности и доменная логика:
  - `Provider` — провайдер и его оф-пиковое окно;
  - `ProviderModel` — модель провайдера;
  - `Price` — строка истории цен (`valid_from`, схема тарификации, ставки);
  - `UsageEvent` — событие использования, его статус и рассчитанная стоимость;
  - `UsageEventReprice` — журнал ретро-коррекций;
  - `OffPeakWindow` — расчёт попадания времени UTC в окно скидки;
  - `PricingCalculator` — расчёт стоимости события.
- `src/Application/*` — сценарии импорта, тарификации, отчёта и пересчёта.
- `src/Infrastructure/Console/*` — команды `bin/console`.

### Команды

- `app:prices:import <file>` — идемпотентный upsert провайдеров, моделей и
  строк цен. Некорректный JSON или семантически неверные данные — код 1.
- `app:usage:import <file>` — импорт JSONL с дедупликацией по
  `(provider, provider_request_id)`. Некорректная строка — код 1.
- `app:billing:rate` — тарификация всех unrated-событий; в stdout
  `RATED=<n> UNRATED=<m>`, в stderr строки `UNRATED ... no_price`.
- `app:billing:report [--from] [--to]` — CSV в stdout, суммы по парам
  `(user, model)` и итоговая строка `TOTAL`.
- `app:billing:reprice <file>` — применяет исправленные строки цен и
  пересчитывает затронутые события; выводит `REPRICED_EVENTS` и
  `REPRICE_DELTA_USD`.

### Работа с деньгами и временем

- Все денежные вычисления — только через `bcmath` с масштабом 24.
  Float не используется.
- Округление ровно одно: стоимость события до 6 знаков по HALF_UP
  (`2.5 -> 3`, для отрицательной дельты — от нуля). Отчёт суммирует уже
  округлённые стоимости без повторного округления.
- Время хранится и сравнивается в UTC. `valid_from` включается в выборку
  (`valid_from <= ts`), `--from` включается, `--to` исключается.
- Оф-пик: окно `[start, end)`; при `start > end` окно переходит через
  полночь. Множитель применяется ко всей стоимости события до округления.

## Ключевые решения и допущения

- Событие хранит коды провайдера и модели, а не жёсткие FK. Это позволяет
  импортировать события до появления соответствующей модели/цены; такие
  события остаются unrated и повторно обрабатываются следующей командой
  `app:billing:rate`.
- Событие хранит `price_id`, которым оно было рассчитано. Это позволяет
  точно находить события, затронутые ретро-коррекцией.
- При `app:prices:import` существующая строка с тем же
  `(provider, model, valid_from)` обновляется новыми значениями (upsert).
  Ретро-пересчёт уже рассчитанных событий намеренно выполняет только
  `app:billing:reprice`, чтобы обычный импорт не менял молча показанные
  расходы.
- `app:billing:reprice`:
  - провайдеры и модели ищутся в уже загруженном справочнике, секции
    `providers`/`models` файла коррекции игнорируются;
  - поддерживается как изменение существующей строки, так и добавление
    новой строки с новым `valid_from`;
  - пересчитываются рассчитанные события затронутых моделей, у которых
    изменилась использованная или выбранная строка цены (включая случай,
    когда новая строка изменила выбор цены для более раннего события);
  - каждое изменение фиксируется в `usage_event_reprices` (старая/новая
    цена, старая/новая стоимость), чтобы корректировка не была
    «молчаливой»;
  - `REPRICED_EVENTS` — количество затронутых коррекцией событий, даже если
    стоимость конкретного события не изменилась; дельта считается как
    сумма новых минус старые стоимости затронутых событий.
- Если `window_start == window_end`, окно считается пустым (скидки нет).
- `currency` принимается и хранится, но пересчёт валют не выполняется:
  по условию задачи везде USD.
- События с полностью нулевыми токенами тарифицируются как обычные и
  получают стоимость `0.000000`.
- Некорректные семантические данные (неизвестный провайдер/модель в файле
  цен, отрицательные токены, неверные ставки) считаются ошибкой импорта
  с кодом 1 и откатывают транзакцию.

## Отступления от каркаса

Файлы каркаса (`TASK.md`, `AGENTS.md`, `README.md`, `fixtures/`,
`composer.json`/`composer.lock`, `docker-compose.yml`, `Makefile`,
`phpunit.xml.dist`, конфиги Symfony) не изменялись. Добавлены только новые
файлы в `src/`, `tests/`, одна миграция в `migrations/`, а также

используются уже установленные Symfony, Doctrine, PHPUnit и расширение
`bcmath` из `composer.json`.

## Как проверял

На чистой базе:

```bash
make db-up
make migrate
bin/console app:prices:import fixtures/prices.json
bin/console app:usage:import fixtures/usage.jsonl
bin/console app:billing:rate
bin/console app:billing:report --from=2026-09-01T00:00:00Z --to=2026-10-01T00:00:00Z
```

Отчёт побайтово совпал с примером из `TASK.md`. Повторный импорт тех же
файлов, повторный `app:billing:rate` и повторный отчёт дали тот же
результат (`RATED=0 UNRATED=0`).

Дополнительно проверено:

```bash
# бонус: исправление ставки input для prism/lumen-8 с 2026-09-15T12:00:00Z
bin/console app:billing:reprice /tmp/correction.json
# REPRICED_EVENTS=1
# REPRICE_DELTA_USD=1.000000
bin/console app:billing:report --from=2026-09-01T00:00:00Z --to=2026-10-01T00:00:00Z
# стоимость u-bob увеличилась с 11.000000 до 12.000000, задвоений нет

# повторная та же коррекция
bin/console app:billing:reprice /tmp/correction.json
# REPRICED_EVENTS=0
# REPRICE_DELTA_USD=0.000000

# некорректный JSON/JSONL — код выхода 1
bin/console app:prices:import /tmp/bad.json
bin/console app:usage:import /tmp/bad.jsonl

make test
# OK (20 tests, 20 assertions)
```
