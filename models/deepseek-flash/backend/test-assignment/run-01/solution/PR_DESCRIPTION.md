# Учёт расходов на LLM-токены

## Что сделано

Реализовано консольное приложение на Symfony/Doctrine/PostgreSQL:

- `app:prices:import <file>` — идемпотентный upsert провайдеров, моделей и
  строк цен;
- `app:usage:import <file>` — потоковый импорт JSONL с дедупликацией по
  `(provider, provider_request_id)`;
- `app:billing:rate` — тарификация всех ещё не рассчитанных событий,
  повторные попытки для unrated, отчёт об unrated в stderr;
- `app:billing:report [--from] [--to]` — CSV-отчёт с группировкой по
  пользователю и модели, сортировкой и строкой `TOTAL`;
- `app:billing:reprice <file>` — бонус: ретро-коррекция цен с пересчётом
  затронутых событий, журналом корректировок и выводом числа событий и
  дельты стоимости.

## Архитектура и ключевые решения

Слои разделены по каталогам:

- `src/Domain` — предметная логика: `Decimal`, `TokenUsage`, `RateCard`,
  `OffPeakWindow`, `CostCalculator`;
- `src/Application` — сценарии импорта, тарификации, отчёта и коррекции;
- `src/Infrastructure` — парсеры файлов, Doctrine-сущности и репозитории;
- `src/UI/Console/Command` — консольные команды.

Деньги и тарифы считаются только через `App\Domain\Money\Decimal`
(bcmath, внутренний масштаб 30). Float для денег не используется ни в
расчётах, ни при разборе JSON: ставки принимаются только десятичными
строками. Округление одно — HALF_UP до 6 знаков для стоимости события;
отчёт суммирует уже округлённые стоимости событий.

Цена выбирается как строка модели с наибольшим `valid_from <= ts`
включительно. Оф-пик задан в UTC, начало включительно, конец исключительно,
поддерживается переход через полночь. Множитель применяется ко всей
стоимости события до финального округления.

Импорт событий выполняется потоково в одной транзакции через
`INSERT ... ON CONFLICT DO NOTHING`; уникальный индекс по
`(provider_code, provider_request_id)` обеспечивает идемпотентность.
Некорректная строка JSONL приводит к откату всей транзакции и коду выхода 1.
Повторная доставка известного события не обновляет его.

Схема БД создаётся Doctrine-миграцией `migrations/Version20261018131213.php`.
Дополнительно на таблицу событий добавлено ограничение неотрицательности
токенов. В отчёте используются данные события, поэтому unrated-события в
него не попадают.

## Допущения

- `provider_request_id` уникален в пределах провайдера; одинаковые id у
  разных провайдеров считаются разными событиями.
- Unrated — это событие без подходящей строки цены, а также событие с
  неизвестным провайдером или моделью. Такие события сохраняются и
  повторно обрабатываются каждым запуском `app:billing:rate`.
- Модель в отчёте выводится как `<provider>/<code>`; сортировка выполняется
  лексикографически по `user`, затем по `provider/code` (collation `C`).
- Валюта сохраняется в справочнике, но пересчёт курсов не выполняется:
  по условию все цены в USD.
- Для `--from`/`--to` дополнительно принимается ISO-дата без времени
  (`YYYY-MM-DD`) как полночь UTC; основной формат задания — полный
  ISO-8601 с `Z`.
- Все поля файлов и команд трактуются как непустые строки, кроме `user`
  (пустой идентификатор допустим).

### Ретро-коррекция

Провайдер и модель для файла коррекции ищутся только в уже загруженном
справочнике; секции `providers`/`models` могут отсутствовать или быть
пустыми. После upsert строк цен пересчитываются все рассчитанные события,
чей `ts` попадает в интервал затронутой строки
`[valid_from, next_valid_from)`. Стоимость в `usage_events` обновляется,
изменения пишутся в журнал `usage_event_reprices`. Выводятся
`REPRICED_EVENTS` и `REPRICE_DELTA_USD` (новая минус старая сумма).
Повторный отчёт после коррекции показывает новые суммы без задвоений.

## Отступления от каркаса

- Изменяемых файлов каркаса нет: `composer.json`, `composer.lock`,
  `docker-compose.yml`, `Makefile`, `README.md`, `fixtures/`,
  `phpunit.xml.dist`, `TASK.md`, `AGENTS.md` не менялись.
- Добавлены только собственный код в `src/`, тесты в `tests/`, миграция в
  `migrations/` (каталог был пуст) и файлы отчёта о сдаче.
- Новые зависимости не добавлялись; используются уже установленные
  Symfony, Doctrine, PHPUnit и расширение bcmath.
- Помимо обязательных команд реализован бонус `app:billing:reprice` и
  журнал ретро-корректировок.

## Как проверял

На чистой базе:

```bash
make db-up
bin/console doctrine:database:drop --force --if-exists
make migrate
bin/console app:prices:import fixtures/prices.json
bin/console app:usage:import fixtures/usage.jsonl
bin/console app:billing:rate
bin/console app:billing:report --from=2026-09-01T00:00:00Z --to=2026-10-01T00:00:00Z
```

Результат `app:billing:rate`: `RATED=3 UNRATED=0`. CSV байт-в-байт совпал
с примером из `TASK.md`:

```csv
user,model,tokens_input,tokens_output,tokens_cache_read,tokens_cache_write,cost_usd
u-alice,prism/lumen-8,1200000,800000,2500000,83333,14.262499
u-alice,sfera/gyro-pro,3000000,500000,0,0,8.400000
u-bob,prism/lumen-8,2000000,1000000,0,0,11.000000
TOTAL,,6200000,2300000,2500000,83333,33.662499
```

Повторный импорт обоих файлов, `rate` и `report` дали `RATED=0 UNRATED=0`
и тот же CSV. Импорт файла с некорректной строкой JSONL вернул код 1 и
откатил уже вставленные строки.

Проверка бонуса: коррекция ставки `input` для `prism/lumen-8` с
`2026-09-15T12:00:00Z` на `2.000000` дала `REPRICED_EVENTS=1` и
`REPRICE_DELTA_USD=1.000000`; возврат исходной ставки дал `-1.000000`, а
итоговый отчёт снова совпал с эталоном.

Автотесты: `make test` (`vendor/bin/phpunit`) — 25 тестов, 57 утверждений,
все проходят. Дополнительно проверены `php -l` для всех файлов `src/` и
`tests/`, `doctrine:schema:validate` (схема соответствует маппингу) и PSR-12
(в новом коде ошибок нет; замечания остались только к нетронутому
`src/Kernel.php` и длинным строкам JSON в тестовых heredoc).
