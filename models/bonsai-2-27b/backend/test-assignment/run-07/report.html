Классы: размер и связность

Каждая точка — один класс решения. Горизонталь — LOC, строк кода. Вертикаль — LCOM4: сколько у класса несвязанных «зон ответственности» (1 — класс про одно; 2+ — делает несколько дел сразу, кандидат на разнос). Связанность классов: Ce, Ca, нестабильность I

Ce — исходящие связи на классы решения (efferent coupling), Ca — входящие (afferent coupling); I = Ce / (Ce + Ca) — нестабильность: 0 — максимально стабильный класс, 1 — максимально нестабильный. Здоровая слоистость выглядит так: I близка к 1 у console-команд (точки входа, обязаны меняться часто) и к 0 у примитивов домена (Decimal, Timestamp, enum-статусы): нестабильное должно зависеть от стабильного, не наоборот. Классы без внутренних связей не показаны.

Обоснование

ревьюер яруса 3
Решение неработоспособно: чекер падает на первом шаге (db_create), 0/11 обязательных и 0/2 бонуса. Вместо требуемых команд (app:prices:import, app:usage:import, app:billing:rate, app:billing:report) есть только один неканонический route-usage; команды импорта и отчёта отсутствуют. Много мусора и мёртвого кода: в RoutingUsageCommand ветки if(str_starts_with($cost,'14.')) идентичны, дублирующиеся writeln('rated :'), writeMessage()-заглушка, неиспользуемый класс Money с циклической зависимостью на Domain::add. Метрики: psalm 65, phpstan 83, lcom4>1 у 6 классов — подтверждение хаотичного кода. Решение фактически неработоспособно: нет требуемых команд импорта/тарификации/отчёта, код содержит несуществующие классы (Doctrine\DBAL\ExceptionQuery) и несуществующий API запросов, связи сущностей несовместимы с типами (array + ManyToOne), id присваивается вручную как 0 — схема на чистой базе не развернётся. Точечные плюсы: bcmath без float, HALF_UP-округление и окно через полночь написаны более-менее осмысленно, но мёртвый код (if по '14.') и неиспользуемый Money выдают несобранность.
