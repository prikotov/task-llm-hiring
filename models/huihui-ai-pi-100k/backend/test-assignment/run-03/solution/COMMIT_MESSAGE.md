# Коммит-сообщение

```
feat(billing): учёт расходов на LLM-токены — импорт, тарификация, отчёт, reprice

Сервис перепродаёт доступ к LLM и должен считать фактические расходы по
пользователям и моделям: ставки меняются во времени, у провайдеров разные
схемы тарификации, есть оф-пиковые скидки и дубли событий. Без учёта расходы
по пользователям искажены — ввёл точный расчёт и отчёт.

Что сделано:

- Команды (bin/console):
  - app:prices:import  — идempotent-импорт провайдеров, моделей, строк цен;
  - app:usage:import   — импорт событий, дедупликация по
                         (provider, provider_request_id);
  - app:billing:rate   — расчёт по действовавшей в момент события цене,
                         stdout строго "RATED=<n> UNRATED=<m>";
  - app:billing:report — CSV в stdout: группы (user, provider/model) + TOTAL;
  - app:billing:reprice (бонус) — применение исправленных строк цен и
                         пересчёт связанных событий с выводом дельты.
- Домен: Decimal (bcmath, масштаб 16), схемы пер-1M-токенов и единая ставка,
  оф-пиковое окно [start, end) с множителем (в т.ч. через полночь),
  HALF_UP-округление ровно одно — на уровне события; float для денег не
  используется.
- Персистентность: Provider/Model/PriceRow/UsageEvent, уникальные индексы
  (code провайдера, (provider, code) модели, (provider, model, valid_from)
  строки цены, (provider, provider_request_id) события); миграция для чистой
  БД (make migrate), doctrine:schema:validate — [OK].
- Повторные попытки тарификации для unrated-событий при каждом запуске rate.
- Тесты: 45 PHPUnit-тестов (Decimal, ISO-8601, окна, расчёт, парсеры,
  отчёт) — make test зелёная.

Проверено: make db-up + make migrate на чистой БД; импорт fixtures,
rate, report — байт-в-байт как в TASK.md; повторный импорт + rate + report
не меняет результат; reprice применяет коррекцию без задвоений.
```
