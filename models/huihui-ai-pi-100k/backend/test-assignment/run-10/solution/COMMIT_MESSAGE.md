Учёт расходов на LLM-токены: импорт цен/событий, расчёт, отчёт, ретро-коррекция

Реализован полный цикл биллинга LLM-токенов на Symfony 8 + Doctrine + PostgreSQL 17:

- app:prices:import — импорт истории цен (провайдеры, модели, строки с
  датами действия) со сравнением по естественным ключам; повторная
  загрузка тех же сумм не дублирует данные;
- app:usage:import — импорт событий потребления (JSONL) с дедупликацией
  по (provider, provider_request_id): повторная доставка молча пропускается;
- app:billing:rate — расчёт стоимости событий по цене, действовавшей в
  момент события (не текущей); точная десятичная арифметика (bcmath,
  масштаб >= 16), оф-пиковый множитель, единственное округление
  HALF_UP только итогового события до 6 знаков; unrated-события
  отчитываются в stderr, код выхода 0;
- app:billing:report — CSV-отчёт (UTF-8) по (user, model) с TOTAL и
  опциями --from/--to; ровно 6 знаков; unrated в отчёт не попадают;
- app:billing:reprice (бонус) — ретро-коррекция цен: upsert строки цены
  и пересчёт уже рассчитанных событий, затронутых изменённой строкой, с
  выводом число событий и дельты стоимости.

Структура: предметный слой (App\Domain), DTO (App\Dto), сущности
(App\Entity), репозитории (App\Repository), сервисы импорта/расчёта/отчёта
(App\Service), команды (App\Command) над общей базой AppCommand
(stdout — результат, stderr — служебное, code 0/1).

Добавлены: миграция схемы БД, unit-тесты ядра (App\Tests\Domain: Decimal,
CostCalculator, OffPeak), вспомогательный фикстура-файл для reprice.
Зависимости не добавлены (bcmath и PHPUnit уже были в каркасе).

Вся приёмка из TASK.md проходит; отчёт за указанный период байт-в-байт
совпадает с эталонным примером.
