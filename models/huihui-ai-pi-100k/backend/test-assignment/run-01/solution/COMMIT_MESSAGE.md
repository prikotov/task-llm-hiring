Учёт расходов на LLM-токены: импорт цен и событий, тарификация, отчёт, ретро-коррекция цен

Реализовано тестовое задание из TASK.md:

- Консольные команды (bin/console):
  - app:prices:import — идемпотентный upsert справочника цен
    (провайдеры по code, модели по (provider, code), строки цен по
    (provider, model, valid_from); некорректный JSON — код выхода 1).
  - app:usage:import — загрузка событий JSONL с дедупликацией по
    (provider, provider_request_id) через уникальный индекс +
    ON CONFLICT DO NOTHING; повторные доставки полностью игнорируются;
    некорректная строка — код выхода 1.
  - app:billing:rate — тарификация всех ещё не рассчитанных событий
    (включая повторные попытки unrated): выбор строки цен с наибольшим
    valid_from <= ts, схемы per_1m_tokens и per_1m_tokens_unified,
    оф-пиковая скидка провайдера (окно [start, end) UTC, поддержка окна
    через полночь). В stdout: `RATED=<n> UNRATED=<m>` (+ строки unrated
    в stderr).
  - app:billing:report — CSV строго в stdout: агрегация по
    (user, модель), сортировка по user затем по модели, суммы уже
    округлённых стоимостей событий, TOTAL-строка; --from/--to —
    включительно/исключительно по ts события.
- Бонус: app:billing:reprice — upsert исправленных строк цен (секции
  providers/models в файле необязательны), пересчёт событий,
  тарифицированных заменёнными строками, журнал корректировок
  (price_corrections: старая/новая стоимость). В stdout ровно:
  `REPRICED_EVENTS=<n>` и `REPRICE_DELTA_USD=<x.xxxxxx>`; n — число
  событий, чья округлённая стоимость фактически изменилась; повторный
  запуск идемпотентен (0 / 0.000000), без задвоений в отчёте.
- Деньги — только точная десятичная арифметика (bcmath, без float):
  промежуточные вычисления без округления (шкала 30), единственное
  округление — стоимость события до 6 знаков HALF_UP.
- Схема БД разворачивается на чистой базе миграцией:
  migrations/Version20261017074532.php (make migrate).
- Тесты: 45 (юнит-тесты домена + интеграционный прогон полного
  конвейера на встраиваемой БД: импорт, тарификация, отчёт,
  идемпотентность, границы периода, unrated→rated, reprice).
- Статический анализ: Psalm (errorLevel 6) — без ошибок;
  PHPCS (PSR12) — без замечаний.

Отчёт за сентябрь по fixtures/ байт-в-байт совпадает с примером из
задания; повторный импорт + rate + report результат не меняет.
