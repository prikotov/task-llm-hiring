# Биллинг LLM-провайдеров (тарификация, отчёт, ретро-коррекция цен)

## Что сделано

CLI-приложение на PHP 8.5 / Symfony 8 / Doctrine ORM 3 / PostgreSQL 17, реализующее все пункты TASK.md:

| Команда | Назначение |
|---|---|
| `bin/console app:prices:import <file>` | idempotent-импорт справочника (провайдеры, модели, строки цен). Вывод: `ИМПОРТ: OK` + детали |
| `bin/console app:usage:import <jsonl>` | приём журнала событий с дедупликацией по `(provider, provider_request_id)` (целый файл — одна транзакция). Вывод: `ПРИНЯТО: N ДУБЛЕЙ: M` |
| `bin/console app:billing:rate` | тарификация всех `unrated`-событий; события без применимой ставки остаются `unrated`. Вывод: `RATED=N UNRATED=M` |
| `bin/console app:billing:report --from <ts> --to <ts>` | CSV-отчёт rated-событий за период `[from, to)` (включает `from`, исключает `to`), сгруппированный по (user, provider/model), + строка `TOTAL`. Вывод — только CSV |
| `bin/console app:billing:reprice <file>` (бонус) | upsert исправленных строк цен по `(provider, model, valid_from)` и пересчёт событий, тарифицированных этими строками. Вывод ровно две строки: `REPRICED_EVENTS=<n>` / `REPRICE_DELTA_USD=<x.xxxxxx>` (дельта новая−старая, 6 знаков) |

Схема БД — миграцией `doctrine/migrations` (`make migrate`) на чистой базе; после разворачивания все команды работают.

## Архитектура

- `src/Entity` — сущности `Provider`, `Model`, `PriceRow`, `UsageEvent` (атрибуты ORM 3);
- `src/Domain` — чистая бизнес-логика: `Decimal` (bcmath), `OffPeak` (окно в минутах UTC), `Rater` (рассчитывает стоимость события по строке цен);
- `src/Ingest` — парсеры JSON/JSONL и DTO (`PriceFileParser`, `UsageLineParser`, …), каждое неверное поле — понятная ошибка с именем поля;
- `src/Service` — `CatalogService`, `PriceImportService`, `UsageImportService`, `RatingService`, `ReportService`, `RepriceService`;
- `src/Command` — консольные команды.

## Ключевые решения и допущения

1. **Точная арифметика.** Все суммы — строки в `bcmath` с рабочим масштабом 26 и единственным
   финальным округлением `HALF_UP` до 6 знаков (`Decimal::roundHalfUp6`). `float` в расчётах не участвует,
   исключение — интервалы дат (timezones/time math).
2. **Оф-пик** — окно `[старт, финиш)` в минутах UTC (старт включён, финиш исключён, возможна пересадка через полночь);
   множитель применяется **к итоговой стоимости события**, затем единственное округление.
   Если окно задано — применяется независимо от схемы тарифа (per-token / unified).
3. **Три состояния `off_peak`** при импорте цен: поле отсутствует в файле — сохранено ранее; `off_peak: null` — окно снято;
   объект окна — окно применено. Для reprice это значит: исправление цен **не сбивает** оф-пик провайдера.
4. **unrated → rated.** Событие без применимой ставки (нет строки цены на `ts`, у строки нет нужного ключа ставки)
   помечается `unrated` и подхватывается повторным `app:billing:rate`. При per-token-ставке ключи
   `input/output/cache_read/cache_write` требуются только для видов токенов, которые > 0 в событии (у событий
   из фикстур `sfera/gyro-pro` только `input`, и у unified-модели это корректно).
5. **Атомарность импорта.** Импорт цен и JSONL — каждая в одной транзакции: либо всё, либо ничего;
   ошибка любой строки JSONL откатывает весь файл (вывод: код 1 + описание с номером строки).
6. **Выводы команд** — ровно тот формат, что зафиксирован в TASK.md, без лишних строк.
   В stderr может идти только отладка (и только при `SYMFONY_DEBUG=1`).
7. **reprice.** Пересчёт — в-place обновление `cost` событий, тарифицированных заменёнными строками,
   с вычислением дельты (новая − старая). Отчёт после reprice показывает корректные суммы без задвоения.
   Механизм (в-place vs журнал корректировок) — на усмотрение; выбран in-place, т.к. в TASK.md
   допустимо «на ваше усмотрение» и это минимально нарушает отчёт.

## Как проверяли

1. **Чистая БД, полный цикл:** `make db-up` → `make migrate` →
   ```
   php bin/console app:prices:import fixtures/prices.json
   php bin/console app:usage:import fixtures/usage.jsonl
   php bin/console app:billing:rate
   php bin/console app:billing:report --from 2026-09-01T00:00:00Z --to 2026-10-01T00:00:00Z
   ```
   → отчёт совпадает с примером из TASK.md **байт-в-байт** (проверено `diff` и контрольной суммой).
2. **Идемпотентность.** Повторный импорт тех же файлов + rate + report — результат не меняется,
   дублей нет, `RATED=0`.
3. **Оф-пик.** События в окне / до окна / на границе `start` / на границе `end` расставлены
   корректно: `end` эксклюзивна, окно с переносом через полночь работает.
4. **unrated → rated.** Импорт журнала без строки цены → событие `unrated`; импорт строки цены →
   повторный `rate` рассчитывает событие; отчёт корректен; `reprice` удваивает стоимость
   (дельта соответствует).
5. **reprice.** `REPRICED_EVENTS=3`, `REPRICE_DELTA_USD=0.000000` на неизменённых ценах;
   на изменённой ставке — ожидаемая дельта; оф-пик провайдера сохраняется.
6. **Экзотические случаи.**
   - `app:usage:import` с пустым файлом → `ПРИНЯТО: 0 ДУБЛЕЙ: 0`.
   - Строка JSONL с некорректным `ts` → код 1, описание с номером строки.
   - Две строки с одинаковым `provider_request_id` в одном файле → всё откатывается (атомарно).
   - `app:billing:report --from` без `--to` → отчёт до «текущего момента», без ошибки.
7. **Тесты.** `phpunit` — 23 теста (все зелёные);
   функциональный тест гоняет полный цикл на реальной БД и сверяет отчёт с примером TASK.md.
