# Учёт расходов на LLM-токены

## Что сделано

- Добавлены команды импорта истории цен и JSONL-событий, тарификации, CSV-отчёта и бонусная команда ретро-коррекции `app:billing:reprice`.
- Реализованы выбор исторической цены на момент события, обе схемы тарификации, оф-пиковое окно UTC с переходом через полночь, точный расчёт на BCMath и округление стоимости каждого события до 6 знаков HALF_UP.
- Приём событий идемпотентен по `(provider, provider_request_id)`. Unrated-события остаются в базе без стоимости, выводятся в stderr и повторно проверяются при последующих запусках тарификации.
- Добавлены миграция чистой схемы PostgreSQL, ORM-модели и модульные тесты расчёта.

## Ключевые решения и допущения

- Стоимости и тарифы хранятся в PostgreSQL `NUMERIC`; оф-пиковый множитель сохраняется исходной десятичной строкой. Денежные операции выполняются только BCMath, без `float`.
- Импорт и тарификация используют Doctrine DBAL и атомарные PostgreSQL `ON CONFLICT`/транзакции (для эффективной идемпотентности и блокировки событий); отчёт читает данные через Doctrine ORM. Схема управляется миграцией, ORM-метаданные синхронизированы с ней.
- Пустые строки JSONL пропускаются. Входные timestamps должны быть UTC с `Z`, дробная часть поддерживается до микросекунд.
- Для окна, у которого начало равно концу, принято решение считать окно пустым. Полуночные окна с разными границами работают как обычный полуинтервал с переходом суток.
- `reprice` атомарно обновляет исправленные строки цен и перезаписывает стоимости событий, тарифицировавшихся именно этими строками; дельта считается как сумма новых стоимостей минус прежние. Это выбранный для задания механизм коррекции без дополнительного журнала аудита.
- У провайдера и модели должны быть загружены соответствующие справочные записи до импорта цены/коррекции; неизвестные модели в событиях допустимы и остаются unrated.

## Проверки

Проверено на чистой базе PostgreSQL:

1. `make db-up`
2. `bin/console doctrine:database:drop --force && make migrate`
3. Импорт `fixtures/prices.json` и `fixtures/usage.jsonl`, `app:billing:rate` и отчёт за сентябрь — CSV совпал с примером из задания.
4. Повторный импорт тех же файлов и тарификация не изменили отчёт; тарификация вернула `RATED=0 UNRATED=0`.
5. Проверены границы периода с микросекундами и бонусный `app:billing:reprice` (число событий, дельта и повторный запуск без повторного пересчёта).
6. `bin/console doctrine:schema:validate` и `vendor/bin/phpunit`.
