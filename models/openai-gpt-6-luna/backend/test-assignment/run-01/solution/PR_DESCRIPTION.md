## Что сделано

- Добавлены команды импорта истории цен и событий использования, тарификации и CSV-отчёта.
- Создана миграция схемы PostgreSQL: справочники провайдеров/моделей/цен и идемпотентный журнал событий.
- Расчёт выполняется через BCMath, округляется один раз до 6 знаков HALF_UP на событие; поддержаны схемы тарифов и off-peak окна, включая переход через полночь.
- Неоценённые события остаются доступными для повторной тарификации после импорта новых цен.

## Решения и допущения

- Для хранения денег и ставок используется PostgreSQL NUMERIC; арифметика приложения — BCMath, тип float для денежных вычислений не применяется.
- `app:prices:import` обновляет данные провайдеров и цен при совпадении ключа; модели и события добавляются идемпотентно.
- Невалидные строки usage импортируются атомарно: весь файл откатывается с кодом 1.
- Бонусная команда `app:billing:reprice` не реализована.
- Дополнительные зависимости не добавлялись. Новые файлы кода находятся в `src/`, тесты специально не добавлялись.

## Проверка

Проверено на локальном PostgreSQL через `make db-up`, `make migrate`, импорт `fixtures/prices.json` и `fixtures/usage.jsonl`, затем `app:billing:rate` и отчёт за сентябрь. CSV совпал с примером из задания. Повторный импорт вернул `RATED=0 UNRATED=0`, отчёт не изменился. Все PHP-файлы проверены `php -l`.
