# Учёт расходов на LLM-токены

## Что сделано

Реализованы обязательные команды:

- `app:prices:import <file>` — upsert провайдеров, моделей, истории цен;
- `app:usage:import <file>` — потоковое чтение JSONL, дедупликация по провайдеру и ID запроса;
- `app:billing:rate` — выбор последней действовавшей цены, обе схемы тарификации, оф-пик, повторные попытки unrated;
- `app:billing:report [--from=…] [--to=…]` — CSV с сортировкой, суммами и TOTAL.

Бонусная ретро-коррекция `app:billing:reprice` не реализована.

## Устройство и решения

- `src/Domain/Tariff.php` — независимый от Symfony и БД расчёт стоимости.
- `src/Entity/{Provider,Model,Price,Usage}.php` — сущности Doctrine ORM и ограничения уникальности.
- `src/Application/Input.php` — проверка входных данных и нормализация времени.
- `src/Application/Billing.php` — сценарии импорта, тарификации и отчёта.
- `src/Command/` — адаптеры Symfony Console, служебные сообщения только в stderr.
- `migrations/Version20261018122344.php` — начальная миграция, включая индексы и внешние ключи.
- `tests/TariffTest.php`, `tests/BillingIntegrationTest.php` — модульные и сквозные проверки CLI с реальным PostgreSQL.

Деньги не преобразуются во float. BCMath использует 6 знаков для произведений токенов и цен, 12 после деления на миллион, затем 12 + число десятичных знаков множителя. Это точные масштабы для заданных операций, а не промежуточное округление. HALF_UP выполняется один раз для неотрицательной стоимости события: прибавление `0.0000005` с усечением до 6 знаков. В БД хранится `NUMERIC(100,6)`. Отчёт складывает сохранённые стоимости через BCMath. Суммы токенов тоже считаются через BCMath, без переполнения PHP int.

Импорт файла атомарен: ошибка любой строки откатывает весь файл. Пишущие команды используют транзакционную advisory-блокировку PostgreSQL, общую для приложения. Она сериализует импорты и тарификацию, защищая от гонок upsert и повторного расчёта. Уникальные ограничения дополнительно защищают естественные ключи. Это сознательный компромисс для небольшого консольного приложения, не высоконагруженный конвейер: записи сохраняются по одной, тариф выбирается отдельным запросом для каждого события.

События могут поступать раньше справочника: provider/model в журнале не имеют внешних ключей. Отсутствующая цена, модель или провайдер дают unrated. Рассчитанное событие хранит стоимость и ссылку на использованную строку цены. Обычный импорт исправленной цены не пересчитывает уже рассчитанные события и не меняет их суммы. Исторический аудит старых версий справочника за рамками обязательной части не ведётся.

## Допущения

- Временные метки принимаются в UTC с `Z`, секунды обязательны, поддерживается до 6 знаков долей секунды. Невалидные календарные даты отклоняются.
- Время хранится канонической строкой фиксированной длины `YYYY-MM-DDTHH:MM:SS.ffffffZ`: это сохраняет микросекунды и даёт корректное сравнение и сортировку без зависимости от часового пояса сессии БД.
- Окно с одинаковым началом и концом пустое: скидка не применяется.
- Цены и множитель — неотрицательные десятичные строки; цены строго с 6 знаками. Множитель не ограничивается сверху единицей.
- Количество токенов одного вида в событии ограничено диапазоном целого PHP (64-битная среда); суммы по событиям этим диапазоном не ограничены.
- Коды и ID запроса — непустые строки до 255 символов. Имя провайдера и ID пользователя не ограничиваются этой длиной. Строки с NUL отклоняются.
- Пустые строки JSONL считаются ошибкой, завершающий перевод строки допустим. Известное событие после разбора JSON и чтения естественного ключа целиком игнорируется, даже если остальные поля изменены.
- `--from >= --to` даёт пустой отчёт с нулевым TOTAL, а не ошибку.

## Развёртывание

Каркас и стандартные команды сохранены:

```bash
make db-up
make migrate
bin/console app:prices:import fixtures/prices.json
bin/console app:usage:import fixtures/usage.jsonl
bin/console app:billing:rate
bin/console app:billing:report --from=2026-09-01T00:00:00Z --to=2026-10-01T00:00:00Z
```

## Проверки

В окружении PostgreSQL уже содержал постороннюю схему. Чтобы не затронуть её, для ручной приёмки создана отдельная чистая БД `billing_solution`; команды запускались с:

```bash
export DATABASE_URL='postgresql://app:app@127.0.0.1:5544/billing_solution?serverVersion=17&charset=utf8'
make db-up
make migrate
bin/console doctrine:schema:validate
bin/console list app
bin/console lint:container
```

Проверено:

- миграция на чистой базе и соответствие схемы ORM;
- пример TASK.md: CSV совпадает байт-в-байт (проверяется интеграционным тестом), TOTAL `33.662499`;
- повторный импорт обоих файлов: `RATED=0 UNRATED=0`, отчёт не меняется;
- границы смены цены, скидки через полночь, обычного окна, периода отчёта и микросекунды;
- разные провайдеры с одинаковым request ID, игнорирование изменённого дубля;
- отсутствие цены, повторная попытка после её загрузки, отсутствие unrated в отчёте;
- нулевые токены, HALF_UP, отсутствие преждевременного округления, сумма уже округлённых событий, большие целые;
- ошибочный JSON/JSONL: код 1, пустой stdout, сообщение в stderr, откат импорта.

Полный запуск тестов:

```bash
TEST_DATABASE_URL='postgresql://app:app@127.0.0.1:5544/postgres?serverVersion=17&charset=utf8' make test
```

Результат: **17 тестов, 78 проверок, успешно**. Интеграционные тесты создают случайную отдельную БД для каждого теста, накатывают реальную миграцию и удаляют БД после теста. Подключению нужны права CREATE/DROP DATABASE. Без `TEST_DATABASE_URL` запускаются модульные тесты, интеграционные явно пропускаются.

Все PHP-файлы проверены `php -l`, контейнер — `lint:container`. PHP_CodeSniffer PSR-12 для добавленного кода не нашёл ошибок; остаются предупреждения о длине строк (главным образом SQL, DQL и тестовые данные).

## Отступления от каркаса

Существующие файлы каркаса, конфигурация, fixtures, composer.json/composer.lock и зависимости **не изменялись**. Новых зависимостей нет: использованы уже установленные Symfony Console, Doctrine ORM/Migrations, BCMath и PHPUnit.

Новые файлы перечислены выше; дополнительно добавлены обязательные `COMMIT_MESSAGE.md` и `PR_DESCRIPTION.md`. Миграция помещена в предусмотренный каркасом каталог `migrations/`, а не в `src/`, чтобы сохранить штатный `make migrate`. Альтернативного способа управления схемой не требуется.
