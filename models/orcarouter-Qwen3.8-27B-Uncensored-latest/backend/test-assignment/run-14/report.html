Классы: размер и связность

Каждая точка — один класс решения. Горизонталь — LOC, строк кода. Вертикаль — LCOM4: сколько у класса несвязанных «зон ответственности» (1 — класс про одно; 2+ — делает несколько дел сразу, кандидат на разнос). Размер точки — WMC: суммарная сложность всех методов класса. Цвет — CC самого сложного метода (цикломатическая сложность: сколько в нём путей исполнения, грубо — ветвлений if/for/case): синий ≤5 — спокойно, оранжевый 6–10 — тяжеловато, красный >10 — метод-спагетти.

Размер точки — WMC класса, цвет — максимальная CC метода: ● ≤5, ● 6–10, ● >10. Наведите на точку — полная сводка.

Матрица зависимостей классов

Связанность классов: Ce, Ca, нестабильность I

Ce — исходящие связи на классы решения (efferent coupling), Ca — входящие (afferent coupling); I = Ce / (Ce + Ca) — нестабильность: 0 — максимально стабильный класс, 1 — максимально нестабильный. Здоровая слоистость выглядит так: I близка к 1 у console-команд (точки входа, обязаны меняться часто) и к 0 у примитивов домена (Decimal, Timestamp, enum-статусы): нестабильное должно зависеть от стабильного, не наоборот. Классы без внутренних связей не показаны.

Обоснование

ревьюер яруса 3
Чекер провалил все 11 проверок: команды app:prices/app:usage/app:billing не зарегистрированы в Symfony DI («There are no commands defined in the "app:prices" namespace»), то есть консольная часть, ради которой делалось задание, не работает — решение частично работающее, ось A = 1. Доменная логика в диффе есть и местами грамотная: точные деньги на bcmath с масштабом 16 и единственным HALF_UP-округлением (Dec::money), собственная строковая реализация halfUp, окно оф-пик с переходом через полночь (OffPeak::activeAt: «$mins >= $start || $mins < $end»), канонизация ISO-UTC. Но есть грубые дефекты: миграция billing_usage_events не создаёт колонку rate_row_id, которую Repository активно использует в fetchRatedEvents/markRated/markUnrated — на чистой базе SQL упадёт; PriceRow продублирован в двух пакетах (Domain/Tariff и Shared/ValueObject) — мёртвый код; Report считает доли пользователей («costSharePct», строка «all/all») — остаток чужого шаблона, не соответствующий формату отчёта задания; upsertPriceRow делает UPDATE цен по ON CONFLICT, что подрывает идемпотентность «повторная загрузка не изменяет данных».
