billing: учёт расходов на LLM-токены по истории цен (консоль)

Решение задачи целиком, без внешних зависимостей сверх поставленных:

- импорт каталога цен (JSON) и событий расходования (JSONL): строгая
  построчная валидация, тихий пропуск дубликатов
  (provider, provider_request_id), идемпотентность повторного импорта;
- тарификация: выбор версии цены (наибольшее valid_from <= ts,
  без отката — unrated «no_price», повторные попытки), точная
  десятичная арифметика bcmath (масштаб 20) с единственным
  HALF_UP-округлением до 6 знаков на событие; два формата тарифа
  (за 1M токенов, за запрос), оф-пик скидка в UTC-окне (с переходом
  через полночь), флаги «скидка применена»;
- отчёт по (user, model) за период --from/--to (без аргументов — все
  события), с итоговой строкой TOTAL, формат 6 знаков;
- бонус: ретро-коррекция цен app:billing:reprice — замена строки цены,
  пересчёт затронутых событий, вывод REPRICED_EVENTS / REPRICE_DELTA_USD
  (дельта «новое минус старое», со знаком);
- схема БД — миграция Doctrine на чистой базе;
- PHPUnit: 48 тестов, включая сквозной EndToEndTest, прогоняющий полный
  сценарий приёмки на чистой app_test-БД через bin/console
  (вплоть до байт-в-байт сравнения отчёта с примером из ТЗ).

Проверено: `make db-up` → миграция → импорты → rate → report — вывод
совпадает с примером ТЗ; повторные прогоны не меняют результат; тесты —
48/48.
