Классы: размер и связность

Каждая точка — один класс решения. Горизонталь — LOC, строк кода. Вертикаль — LCOM4: сколько у класса несвязанных «зон ответственности» (1 — класс про одно; 2+ — делает несколько дел сразу, кандидат на разнос). Размер точки — WMC: суммарная сложность всех методов класса. Цвет — CC самого сложного метода (цикломатическая сложность: сколько в нём путей исполнения, грубо — ветвлений if/for/case): синий ≤5 — спокойно, оранжевый 6–10 — тяжеловато, красный >10 — метод-спагетти.

Размер точки — WMC класса, цвет — максимальная CC метода: ● ≤5, ● 6–10, ● >10. Наведите на точку — полная сводка.

Матрица зависимостей классов

Классы отсортированы по неймспейсам: слои подписаны на диагонали, жирные линии их разделяют; жёлтый столбец «внеш.» — исходящие связи к типам вне решения (DTO времени, коллекции). Наведите на закрашенную ячейку — кто на кого и сколько раз.

Связанность классов: Ce, Ca, нестабильность I

Ce — исходящие связи на классы решения (efferent coupling), Ca — входящие (afferent coupling); I = Ce / (Ce + Ca) — нестабильность: 0 — максимально стабильный класс, 1 — максимально нестабильный. Здоровая слоистость выглядит так: I близка к 1 у console-команд (точки входа, обязаны меняться часто) и к 0 у примитивов домена (Decimal, Timestamp, enum-статусы): нестабильное должно зависеть от стабильного, не наоборот. Классы без внутренних связей не показаны.

Обоснование

ревьюер яруса 3
Обязательная часть в целом работает (10/11 у чекера): дедуп по (provider, request_id), выбор цены max valid_from ≤ ts, оф-пик с переходом через полночь (isTimeInWindow корректно обрабатывает wrap), bcmath с scale 16 и единственным округлением HALF_UP. Дефекты: (1) UNRATED-строки пишутся в stdout через $output->writeln(..., VERBOSITY_QUIET) в BillingRateCommand, а задание требует stderr — единственный fail чекера, и при этом stdout сводки замусоривается; (2) float для денег всё же просачивается в форматирование отчёта: number_format((float)$r['cost'],6,...) и (float)$totalCost — формально нарушение запрета float, работает на этих данных, но хрупко; (3) N+1 — findPrice и em->find(Provider) на каждое событие в цикле; (4) unknown unit молча даёт cost 0, валидации токенов нет. valid_from как строка ISO — лексикографическое сравнение работает только для нормализованных UTC-меток, допущение задекларировано. Домен не выделен: вся логика в god-командах (LCOM4>1 у 8 классов, cc_max 12, 230 замечаний phpcs), бонус не делался. Ось B: COMMIT_MESSAGE.md и PR_DESCRIPTION.md с допущениями и шагами проверки есть, но заявлено «вывод совпадает с примером» при непроверенном сценарии unrated — самопроверка точечная, тестов нет.

Функционально решение, видимо, проходит базовый сценарий: bcmath с масштабом 16, HALF_UP до 6 знаков, окно через полночь, дедупликация по составному ключу, unrated-повторы реализованы.
