# GigaChat-3-Ultra (Сбер, через API TasK)

## Характеристики

- Провайдер: Сбер, endpoint `https://api.giga.chat/v1/chat/completions`
  (единый URL для физлиц и юрлиц с 16.07.2026; старый
  `gigachat.devices.sberbank.ru` остаётся для GigaChat-2)
- Модель: `GigaChat-3-Ultra` — **доступна только физическим лицам и только
  во Freemium** (юрлицам не продаётся, платного пакета нет)
- Ключ — OAuth Basic из `~/MyProjects/TasK/Development/.env.dev.local`
  (scope GIGACHAT_API_PERS), раннер `interview/runner_ru_cloud.py
  --provider gigachat --model GigaChat-3-Ultra`
- Freemium-квота Ultra: **50 млн токенов на 12 мес**

## Test-assignment (этап 2, 2026-10-21)

Доступ через локальный мост `test-assignment/backend/billing/gigachat_proxy.py`:
GigaChat API говорит только легаси-форматом функций (`functions`/`function_call`,
результат — `role:function`; современный `tools` молча игнорирует), плюс
OAuth-токен живёт ~30 минут — мост переводит tools↔functions на лету и
обновляет токен каждые 25 мин. GigaChat возвращает не более **одного вызова
функции за ход**. Проверено пробами 2026-10-21; usage Сбера (в т.ч.
`precached_prompt_tokens`) пробрасывается в сессию pi.

## Вывод по этапу 2

Агентная работа не даётся: в интервью (плоский диалог) — лучший результат
среди российских моделей и 3/3 провокаций, в длинном агентном горизонте —
вырожденный цикл. Контекст ~131K вмещает задание, интеграция работает;
узкое место — дисциплина модели на сотнях tool-вызовов.

**Контрольный эксперимент против «кривой интеграции» (2026-10-21):** полный
диалог прогона (1350 сообщений) восстановлен из сессии и отправлен через тот
же мост одним запросом — Сбер принял все **86 539 токенов промпта** без
усечки, а модель в ответ выдала **тот же самый** `doctrine:query:dql
"SELECT p.code…"`, глядя на 623 идентичных пустых результата в истории.
Цикл — поведение модели, не артефакт моста.

**Это известный семейный дефект GigaChat:** в официальном
[langchain-gigachat](https://github.com/ai-forever/langchain-gigachat/pull/69)
открыт PR #69 «break infinite agent loop on repeated identical tool calls»
(март 2026): «GigaChat can enter an infinite loop calling the same tool on
every turn» — тот же паттерн «один инструмент, те же аргументы, каждый ход».
Решение сообщества — не в модели, а в харнесе: счётчик подряд идущих
одинаковых вызовов (`repeated_tool_call_limit=3`), после лимита вызовы
вырезаются из ответа, чтобы агент вышел из цикла. PR не смержен.

Замечание по учёту: usage Сбера занижает входные токены — при промптах
в десятки тысяч токенов в конце цикла API рапортовал ~5K (кэшированную
часть не показывает, `precached_prompt_tokens: 0`). Записанные 7.75M —
нижняя оценка фактического потребления; для freemium-квоты фигурирует
счётчик Сбера. Из-за этого же на графике контекста в report.html прогона
видна «пила» — это не автокомпакции (их в сессии 0, контекст рос
монотонно до ~86.5K), а скачки кэш-попаданий Сбера в отчётном usage.

## Если использовать в работе (юрлицо)

Сбер юрлицам GigaChat-3-Ultra не продаёт (в тарифах юрлиц только
GigaChat-2 Lite/Pro/Max); коммерческий доступ к линейке Ultra — только
через **cloud.ru Foundation Models** (туда же с 01.09.2026 направляют всех
новых клиентов Сбера): GigaChat 3.5 Ultra — **₽96/1M вход + ₽289/1M выход**
(≈$1.16/$3.47). Наша сессия в таких ценах: **₽71 (~$0.83)** без учёта кэша,
**₽140 (~$1.65)** если кэш тарифицируется как входные токены. Ирония:
флагман через cloud.ru выходит дешевле GigaChat-2 Max по сберовскому
тарифу (₽650/1M без разбивки) — у cloud.ru раздельный прайс с дешёвым
входом, а собес входо-ёмкий (92% входных токенов).
