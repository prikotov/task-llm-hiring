# Аудит вопросника «карты знаний PHP» — три внешние модели (2026-11-06)

Вопросник v1 (96 утверждений, 12 тем × 8 уровней) прогнали через три
модели-рецензента — Xiaomi MiMo v2.6 Pro, Kimi 3.1 Pro, DeepSeek-V4.1-Flash
(агент pi из консоли, по 5 одинаковых промптов на модель: формат → факт-чек
T01–T06 → факт-чек T07–T12 → ось уровней → развитие). Спорные факты
перепроверены эмпирически: php 8.5.11 на машине теста и wiki.php.net.
Сырые ответы: `knowledge-map-review/<модель>/step*.md` (рядом с этим файлом).

## Итог в одну строку

Формат признан рабочим всеми тремя; найдена **одна фактическая ошибка**
(T01-L7, подтверждена кодом), **полярный конфаунд** раскладки (нашли все
три независимо), ось L1–L8 признана несуществующей в нынешнем виде
(смешаны 4 шкалы) — консенсус: одна внешняя ось «экспозиция/повседневность»
+ тег типа знания, а «сложность» — измеряется, не назначается; версионные
вопросы — отдельный тип с датой снимка (поддержано всеми, примеры даны).

## 1. Формат «утверждение → да/нет»

Все три: пригоден как тест **распознавания и дискриминации** фактов, дёшев,
клетки изолированы — «главное достоинство метода Карпаты» (deepseek).
Принципиально не меряет: продукцию (сформулировать самому), многошаговый
вывод, отладку, «не знает» vs «знает, но поддался риторике» — обе причины
красного неразличимы. Формулировки: kimi — «даже высокий результат нельзя
называть уровнем программирования».

Общие риски и гашение:
- **Угадывание**: 96 клеток → 95%-интервал ±10 п.п. на прогон (±28–35 на
  тему/уровень) — разница в 1–2 клетки между моделями есть шум. Гашение:
  серии прогонов, попарные сравнения по клеткам, интервалы в отчётах.
- **«Да»-bias**: считать не только долю «да», а hit/FA-метрики
  (задача обнаружения: hit rate, false-alarm rate, d′ и критерий c) —
  бесплатно из уже собранных данных (deepseek).
- **Стиль формулировки**: зеркальные пары (одно утверждение в верной и
  ложной редакции с минимальной правкой) и парафразы — расхождение внутри
  пары = реакция на стиль, не на факт.
- **Серые клетки**: это 4 разных феномена (отказ/уклончивость,
  дегенерация, нарушение формата, обрыв) — разложить; всегда публиковать
  пару «strict-точность / точность по разобранным».
- **Контроль-фальшивки**: добавлять несуществующие функции/фичи — прямой
  измеритель «да на всё правдоподобное» (deepseek).

## 3. Ось уровней L1–L8

Вопрос владельца «уровни чего?» — подтверждён всеми тремя: ось смешала
минимум 4 шкалы (частота в практике, контринтуитивность, синтаксис vs
семантика, версионная тривиальность), поэтому и читается как шум.

- **Полярный конфаунд** (нашли все три независимо): в v1 нечётные уровни
  почти всегда «да», чётные — «нет» (L3 — 12/12 «да», L4 — 0/12). «Всегда
  да» даёт идеальную пилу по столбцам, «уровень» меряет аквиесценцию.
  Fix: случайная полярность, 6/6 в каждом столбце (и 4/4 в теме сохранить).
- **Консенсус по оси**: одна упорядоченная **внешняя** ось (модели
  независимо предложили одно и то же — «экспозиция»: как часто работающий
  разработчик встречает факт в коде/доках; якоря — документация и
  частотность, не вкус автора) + **тег типа знания** на клетку (факт /
  ловушка-миф / версия / вывод). «Сложность» и «глубина» — измеряются по
  результатам моделей, а не назначаются («сложное = то, что модель не
  знает» — тавтология). Kimi: 8 бинов фиктивны — практичнее 4 полосы по
  2 колонки; читать карту бендами (по 24 клетки) из-за шума.
- **Клетки не на своём месте** (консенсус ≥2 из 3): T12-L7 (prepared
  statements — повседневщина, стоит L7), T12-L8, T02-L7/T02-L8, T07-L8
  (enum — «новизна» вместо экзотичности), T04-L1, T11-L6, T03-L6, T08-L8;
  дубль знания T10-L2/T10-L7 (разброс 5 уровней на один факт).
- Чтение карты станет осмысленным: «красный на L1–L2 = дыра в базе,
  красный на L7–L8 = ожидаемо», «зелёные тонкости при красной базе =
  переобучение на трюках» (mimo).

## 4. Развитие: версионный тип и cutoff-зонд

Идея владельца поддержана всеми тремя, с уточнениями:

- **Отдельный тип вне основной карты** (вневременная карта 96 не должна
  страдать от дрейфа версий), обязательная метка **даты снимка** (`as_of`),
  ответы фиксируются «состояние RFC на дату X» и перепроверяются перед
  каждой серией.
- **Форматы**: да/нет тесно; основной — «какая минимальная версия?» с
  вариантами / multi-select «какие фичи появились в 8.4»; для cutoff-зонда
  — пары «принятый RFC vs правдоподобная ложь» (ложь ловит галлюцинации
  будущего); парафразы факта («X появилась в 8.1» ↔ «в 8.0 её ещё не
  было»). Полезно «не знаю»/вероятность + поправка на угадывание.
- **Примеры клеток** (даны моделями, спорные проверены на wiki.php.net
  2026-11-06): property hooks 8.4 ✓, asymmetric visibility 8.4 ✓,
  array_find 8.4 ✓ (но array_any/array_all mimo ошибочно записал в PHP —
  их нет, живое подтверждение, что ответы версионной панели валидировать
  на php.net), `|>` 8.5 ✓, array_first/last 8.5 ✓, `#[\NoDiscard]` 8.5 ✓,
  clone with 8.5 ✓, deprecation nullable 8.4 ✓; будущие: PFA v2 — 8.6 ✓,
  clamp() — 8.6 ✓, generics (Bound-Erased) — отклонён 06.2026 ✓,
  context managers v2 — в обсуждении ✓, «ZTS по умолчанию» — такого RFC
  нет ✓; старые: `??` — 7.0, scalar types — 7.0 (не 5.6), typed props —
  7.4, PHP 6 — не выходила. Итого: 3 модели суммарно предложили ~33
  кандидата, ни один «будущий» факт не противоречит wiki.
- **Что убрать из 96** (кандидаты, консенсус ≥2): T02-L2 (дубль-перевёртыш
  T02-L1), T12-L2 (md5 — общая гигиена, не PHP), T12-L5 (php_sapi_name —
  FAQ-тривия), T12-L7 (перенести в версию/заменить), T08-L3 (дубль
  иерархии T08-L2), T08-L7 (версионный факт 8.4 — в версионную панель),
  T06-L2, T07-L2 (тривии), T03-L6, T11-L6 (по одному голосу). При уборке —
  замены, чтобы сетка 12×8 и баланс остались.

## 5. План действий (предложение к обсуждению)

1. **T01-L7 переписать** (ответ ДА: «выражение даёт 'сумма: 5'», note про
   RFC 8.0); заметки T02-L6, T06-L5, T09-L8, T10-L3 уточнить. Это правки
   внутри v1 (ответы не меняются — кроме T01-L7).
2. **questions v2** (после отладки серий): перемешать полярность (6/6 на
   столбец, 4/4 на тему), перенести раскладку клеток по оси
   «экспозиция» с якорным описанием уровней, теги типа знания (F/M/V/E),
   убрать/заменить клетки из консенсус-списка «убрать», добавить 10–12
   дублей-парафраз и 6–8 клеток-фальшивок.
3. **Версионная панель** — отдельный вопросник (15–25 клеток, `as_of`),
   форматы: «минимальная версия» + multi-select + да/нет-пары с
   правдоподобной ложью; ответы валидируются на php.net перед серией.
4. **Метрики отчёта**: добавить hit/FA (d′, критерий c), пару «strict /
   по разобранным», интервалы; сравнение моделей попарно по клеткам.
5. **Серии**: по 3 прогона на уровень — уже зафиксировано в blueprint;
   для вероятностного протокола decision-моделей карта и так вероятностная.

Проверка независимости (`note` автором-ассистентом без внешнего ревью)
закрыта этим аудитом частично: три модели + эмпирика на 8.5. Для v2 —
валидационные скрипты к каждой исполняемой клетке (предложение mimo).
