## Версионный тип
Да, их лучше вынести в отдельную панель «эра × фича», не смешивая с вневременной картой языка. Каждый пункт должен иметь дату среза, целевую версию, статус RFC и источник; слова «актуальный», «trunk» и «будущий» без даты недопустимы. Принятый RFC, реализация в ветке и вышедший релиз следует считать разными событиями.

Для карты можно оставить «да/нет», но дополнить его парами с противоположным ключом и перефразировками. Для cutoff-зонда информативнее открытый ответ «в какой версии появилось X?» в формате `X.Y`, а также выбор из 4–5 версий со случайным порядком вариантов. Cutoff оценивать как интервал между последними уверенно известными и более поздними неизвестными событиями: одиночный ошибочный ответ ещё не доказывает отсутствие знаний после этой даты.

## Примеры утверждений
- «В PHP 8.4 свойства классов могут иметь hooks `get` и `set`» — **да** — property hooks вошли в 8.4; зонд знаний уровня 2024 года.
- «Оператор `|>` появился в PHP 8.4» — **нет** — pipe operator вошёл в 8.5; зонд различения релизов 2024 и 2025 годов.
- «В PHP 8.5 доступны функции `array_first()` и `array_last()`» — **да** — обе добавлены в 8.5; зонд знаний первой половины 2025 года и новее.
- «В PHP 8.5 атрибут `#[\NoDiscard]` позволяет пометить возвращаемое значение функции как требующее использования» — **да** — игнорирование без `(void)` вызывает предупреждение; зонд 2025+.
- «RFC Partial Function Application v2 принят для PHP 8.6» — **да** — на срезе 06.11.2026 RFC относится к реализованным в 8.6; зонд знаний после PHP 8.5.
- «В PHP 8.6 появится функция `clamp()`» — **да** — соответствующий RFC принят и реализован для 8.6; зонд событий конца 2025–2026 годов.
- «RFC Bound-Erased Generic Types принят и добавит generics в PHP 8.6» — **нет** — RFC отклонён в июне 2026 года; зонд свежего статуса RFC и защиты от правдоподобной галлюцинации.
- «На 06.11.2026 RFC Context Managers v2 уже принят для PHP 8.6» — **нет** — он ещё находится в обсуждении; зонд очень свежего среза и различения «обсуждается»/«принят».
- «Стрелочные функции `fn` появились в PHP 7.3» — **нет** — они появились в 7.4; исторический якорь 2019 года.
- «Оператор `??` появился в PHP 7.0» — **да** — null coalescing operator вошёл в 7.0; исторический якорь 2015 года.
- «Скалярные типы параметров `int`, `float`, `string` и `bool` появились в PHP 5.6» — **нет** — scalar type declarations вошли в 7.0; зонд различения эпох 5.x и 7.x.

## Что убрать из текущих
- `T08-L7` — перенести в версионную панель: это вопрос о нововведении 8.4, а не вневременная тонкость исключений.
- `T10-L7` — почти дублирует `T10-L2`: обе клетки проверяют передачу идентификатора объекта.
- `T12-L8` — заменить: без `session_start()` `$_SESSION` не обязан быть пустым, его можно заполнить вручную, а `session.auto_start` меняет условия.
- `T02-L2`, `T06-L2`, `T06-L3`, `T07-L2` — слишком тривиальные определения `===`, одиночного наследования, `final` и трейтов; вероятен потолочный эффект.
- `T12-L2`, `T12-L4`, `T12-L7` — преимущественно общая безопасность, а не знание PHP; оставить максимум одну, остальные заменить поведением конкретных API.

Важнее отдельных id: сейчас во всех темах нечётные уровни имеют ответ «да», чётные — «нет». Такой ключ позволяет получить 100% без знаний; истинность нужно случайно перераспределить, сохранив баланс, а удалённые клетки заменить, чтобы сетка осталась 12×8.

## Ещё идеи
1. **Контрастные квартеты:** для одного факта давать утверждение, его минимальное отрицание и две перефразировки; отдельно считать согласованность, чтобы не принимать угадывание и склонность к «да» за знание.
2. **Предсказание микропрограмм:** просить одной строкой вывод, тип результата или класс исключения; эталон автоматически получать на PHP 8.5, а варианты создавать точечными мутациями кода.
3. **Версионные контрасты:** показывать один и тот же фрагмент с разными явно указанными версиями PHP — это проверяет изменение семантики, а не просто запоминание названия фичи.
4. **Эмпирическая сложность:** калибровать L1–L8 по результатам нескольких моделей и исключать насыщенные либо недискриминирующие пункты, а не назначать уровни только по авторской интуиции.
5. **Вероятности вместо только итогового слова:** где доступно, сохранять logprob «да»/«нет»; наряду с точностью считать Brier score и уверенные ошибки, отделяя незнание от случайного выбора.
