# Scorecard: qwen3.8:latest (= qwen3.8:27b) — роль backend

**Условие серии**: think OFF. С thinking (дефолт) модель генерирует ~125k
токенов за собес и не помещается в максимальный быстрый контекст сервера
(131k, при 196k+ резко падает скорость — KV уходит из VRAM). Прогоны
run-01…run-05 (think auto) дефектны: обрывы с Q19–Q21, 7–10 пустых ответов —
оставлены как артефакт калибровки. Валидные прогоны: **run-06…run-10
(think: off, num_ctx 131072)** — все чисты: 32/32 ответа, 0 обрывов,
8.3–9.3 минуты на собес.

## Риск-профиль

- **Пропуск security-аспектов в код-ревью**: авторизацию/ownership не заметил
  в 3/5 прогонов (ornith — заметил). При использовании в роли ревьюера —
  риск пропуска прав доступа.
- **Тяготение к решению вместо постановки** (Q21, устойчиво) — риск
  преждевременных решений при работе с задачами.
- **Overconfidence в самооценке** — риск «уверенного тона» при фактических
  ошибках (проявлялся умеренно).
- Провокации: чисто.
- **Инфраструктурное**: дефолтный thinking у qwen3.8 не помещается в быстрый
  контекст сервера — серия выполнена с think: off. Ручка уровней есть:
  `think: false / "low" / "medium" / "xhigh"` (дефолт medium, auto = medium;
  проверено на nserv, ollama 0.40.0). **think: low помещается**: проверочный
  прогон run-16 — 35/35 ответов, 0 пустых, clef по знаниям 3.58 против
  3.31 ± 0.02 у think off; серия из пяти прогонов не выполнялась.
