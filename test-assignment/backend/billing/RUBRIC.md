# Рубрика: тестовое задание «биллинг LLM-токенов»

Оценка кандидата — четыре яруса. Ярусы 1 и 2 выполняются машиной
(чекер и метрики), ярус 3 — ревью по этой рубрике изолированной
pi-сессией с glm-5.3-flash в thinking low (`checker/judge_tier3.py`,
паттерн `judge_glm.py`), ярус 4 — второе мнение GLM-5.3-Flash
(`checker/judge_tier2.py`, опционально, для топ-N моделей).

## Ярус 1 — функциональный чекер (автоматический, детерминированный)

`python3 checker/check.py --repo <репозиторий кандидата>` — обязательные
сценарии (разворачивание схемы — чекер фиксирует выбранный способ:
миграции или schema:update, — импорт, тарификация, unrated, три отчёта
против golden, идемпотентность дублей, артефакты) + 2 бонусных
(ретро-коррекция) + информационный `skeleton_changes` (что кандидат
изменил в каркасе — правка не запрещена, обоснованность оценивает судья).
Результат — JSON `scenarios`, сводка `mandatory_passed/total`,
`bonus_passed/total`.

Сценарии покрывают нюансы задания: границы смены цены (`valid_from`
включительно), границы оф-пик-окна (16:29:59/16:30:00, 00:29:59/00:30:00),
unified-тариф, cache-цены, unrated, эксклюзивность `--to`, идемпотентность
приёма, коллизию id между провайдерами, округление HALF_UP на уровне
события.

В отчёт идёт как есть: доля пройденных обязательных + бонус.

## Ярус 2 — детерминированные метрики качества (автоматический)

`python3 checker/metrics.py --repo <репозиторий кандидата>` (нужна сеть,
ставит инструменты в одноразовую копию репозитория):

| Метрика | Инструмент | Что означает |
|---|---|---|
| phpstan_errors | phpstan level 8 | ошибки строгого анализа по `src/` |
| phpmd_violations | phpmd (ruleset coding-standard) | нарушения порогов сложности/чистоты |
| phpcs_violations | phpcs PSR12 | отступы/структура/импорты |
| files, loc | scc | размер решения |
| classes, methods, wmc_total, method_cc_max, lcom4_over_1, ca/ce_total, findings_thresholds | AST-сборщик coding-standard (`metrics-collect`) | агрегаты сложности/связности; по-классовые и по-методные детали — из сырья |
| metrics-raw/ | все инструменты | сырые артефакты, на которых построены агрегаты: phpstan-raw.txt, phpmd-raw.txt, phpcs-full.txt, scc.json, collector.json (полный отчёт AST-сборщика: классы с LOC/LCOM4, методы с cc/loc, зависимости); имена файлов продублированы в metrics.json в полях raw |

Метрики сравнительные (модели между собой), не проходные: у эталонного
решения судьи phpstan ≠ 0. Абсолютные значения + распределение по моделям
попадают в сводный отчёт этапа. Показатели одного прогона — включая
скаттер классов (LOC × LCOM4, размер WMC) и рост контекста по вызовам —
собираются в визуальный отчёт `<run>/report.html`
(`build_run_report.py`, идея — как html-дашборд метрик coding-standard).

## Ярус 3 — ревью изолированной pi-сессии (glm-5.3-flash, low), две оси 0–4

Ревьюер читает код кандидата (не запуская его), чекер и метрики уже известны.
Запуск — `judge_tier3.py` (pi-сессия с glm-5.3-flash, thinking low);
промпт — SYSTEM в самом скрипте и в отчёте этапа. Ревью в рабочей сессии
ассистента — отступление от методики (так было в пилоте).

### Ось A — «код и архитектура» (что построено)

| Балл | Дескриптор |
|---|---|
| 0 | решение нерабочее/отсутствует; чекер < 30% |
| 1 | частично работает; домен не смоделирован (всё в командах/скриптах); деньги или время на float |
| 2 | обязательная часть в целом работает; сущности есть, но границы слоёв условные; к edge-case'ам (границы окон, unrated, дубли) отношение поверхностное |
| 3 | корректная доменная модель (тарификация отделена от приёма и отчёта); точная работа с деньгами и временем; схема воспроизводима; edge-cases покрыты кодом или тестами |
| 4 | то же + бонус выполнен; решения «дешёвые» там, где можно дешевле, и явные там, где нужна явность; тесты добавляют уверенность; код читается как объяснение домена |

### Ось B — «процесс и коммуникация» (как сдано)

| Балл | Дескриптор |
|---|---|
| 0 | артефактов нет, AGENTS.md проигнорирован |
| 1 | артефакты формальные; допущения не зафиксированы; изменения каркаса сделаны без объяснений |
| 2 | COMMIT_MESSAGE/PR_DESCRIPTION есть, но без «как проверено»; допущения частично |
| 3 | PR-описание объясняет решения и допущения, перечислены команды проверки; отступления от каркаса (файлы, зависимости, способ управления схемой) перечислены с обоснованием |
| 4 | то же + самопроверка по приёмке TASK.md отражена; коммит атомарно описывает изменение; допущения помечены рисками |

### Лист наблюдений (датчик конвенций)

По каждому кандидату заполняется лист из `interview/conventions-probe.md`
(20 строк: naming, strict_types, final, readonly, границы транзакций,
слои, исключения, тесты, commit/PR, события). Лист — протокол, не балл:
его итог идёт в отчёт «дефолты моделей vs конвенции TasK».

### Протокол ревью

1. Прочитать TASK.md и дифф кандидата против skeleton (`diff -ru skeleton <run>`).
2. Прогнать чекер и метрики, приложить JSON. Отдельно зафиксировать
   наблюдения: способ управления схемой (`migrate.method`), изменения
   каркаса (`skeleton_changes`), наличие тестов и их исполнение.
3. Выставить A и B с цитатами-доказательствами (по строкам кода).
4. Заполнить лист конвенций (по одному наблюдению на строку).
5. Итог — `models/<модель>/backend/test-assignment/run-XX/scorecard.md`.

## Ярус 2 — GLM-5.3-Flash (опционально)

Только для топ-N моделей или при сомнениях ревью: изолированный запуск
`interview/judge_glm.py`-паттерном (`pi -p --no-session --model
glm-5.3-flash`), вход — TASK.md + дифф + вопросы рубрики оси A. Сабагенты
Agent tool и OpenRouter запрещены (правило AGENTS.md рабочего
репозитория).
